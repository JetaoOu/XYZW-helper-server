# 0001 重写服务端，不复用 render-backend

## 状态

已接受（2026-11-14）

## 背景

旧仓库 `xyzw_web_helper` 里已有一个 `render-backend/`：Express + Supabase + node-cron + 基于 `ws` 的 `GameClient`，能按固定命令清单对多个角色执行任务。

审查后发现它与目标存在结构性差距：

- 任务模型是「扁平命令清单」，没有旧前端 `dailyTaskRunner` 的「读取官方配置 + 服务器状态补差」语义，重复执行会频繁产生假失败。
- 存储强依赖 Supabase（外部服务），与「阿里云单机、单容器」的部署目标不符。
- 协议实现是 `bonProtocol` 的第二份拷贝，存在双实现漂移风险。
- 没有连接池、角色级互斥、运行记录、补跑、凭据失效处理等长期运行所需的机制。

## 决策

在新仓库中重写服务端（Node + TypeScript + Fastify + SQLite），只借鉴 `render-backend` 中已被证明可行的点（`ws` 连接方式、URL 构造、seq/ack 处理），不继承其代码结构。

## 后果

- 需要自己实现调度、并发、重试、凭据管理等模块，第一版工作量约 5–8 人日。
- 避免把「扁平命令清单」的历史包袱带进新模型，也避免 Supabase 依赖。
- 协议层只保留一份实现，降低长期维护成本。
