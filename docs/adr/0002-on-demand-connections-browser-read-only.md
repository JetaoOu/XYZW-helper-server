# 0002 服务端按需连接，浏览器只读

## 状态

已接受（2026-11-14）

## 背景

旧项目由浏览器直接连接游戏 WebSocket，页面关闭后定时任务即中断。服务端化之后，需要决定「谁持有游戏连接」以及「连接是否常驻」。

同一游戏凭据在浏览器和服务器同时连接，存在互相踢下线或串号的风险；而常驻连接只在需要秒级状态回显时才有价值。

## 决策

- 服务端**按需连接**：开始执行计划或手动动作时建立连接，该角色本轮结束后立即断开。
- 浏览器前端**永不直连游戏 WebSocket**，所有状态以服务端上报为准。
- 角色快照由前端手动触发或在计划执行时顺带更新，不做定时采集。

## 后果

- 平时不占用游戏连接数，风控面小，服务器资源占用低。
- 状态展示存在延迟，最坏情况是「上次执行后到现在」；需要更新时由用户手动刷新快照。
- 跨计划/手动触发的并发冲突由服务端的角色锁解决，而不是依赖浏览器标签页协调。
