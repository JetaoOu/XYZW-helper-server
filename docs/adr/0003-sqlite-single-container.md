# 0003 SQLite 单文件 + 单容器部署

## 状态

已接受（2026-11-14）

## 背景

部署目标是阿里云上的单台服务器，单用户使用，不需要水平扩展。数据包括凭据（需加密）、计划、运行记录、命令日志与设置。

可选方案：Supabase/PostgreSQL（外部依赖、需网络）、MySQL RDS（成本与运维更高）、SQLite（单文件、随容器卷持久化）。

## 决策

- 使用 SQLite（better-sqlite3）+ Drizzle ORM，数据库文件放在挂载卷上。
- 单个 Docker 容器：Fastify 同时托管前端静态文件与 API，对外映射 `3000` 端口。
- 每日 03:00 做一次 SQLite 在线备份，保留 7 份，产物落在宿主机挂载目录。

## 后果

- 部署就是 `docker compose up -d`，备份就是拷贝一个文件，零外部依赖。
- 只能单实例运行；若将来需要多副本或更高并发，需要迁移到 PostgreSQL，并在迁移时引入跨实例锁。
- 由于 SQLite 单写入者模型，所有写操作保持短事务，避免长事务阻塞调度。
